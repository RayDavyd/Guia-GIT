Branches & Trabalho em Equipe

Branches permitem que cada pessoa trabalhe numa funcionalidade sem afetar o código dos colegas. Aqui vamos entender o que são, como usá-las e como resolver conflitos quando o trabalho é combinado.

O que são branches? Avançar para GitHub →
Conceito

O que são Branches e por que usá-las

Uma branch (ramo) é, na prática, um ponteiro móvel que aponta para uma sequência de commits. A branch principal é normalmente chamada main. Criar uma nova branch permite isolar o desenvolvimento de uma funcionalidade sem afetar o código estável.

🧪

Experimentação segura

Teste novas ideias sem o risco de "partir" o código que já funciona na main.

👥

Trabalho paralelo

Cada integrante da equipa pode desenvolver a sua funcionalidade ao mesmo tempo, em branches separadas.

🔍

Revisão antes de integrar

O código só chega à main depois de revisado, através de um Pull Request.

Comandos

Comandos essenciais de Branch

git branch

Listar e criar branches

Sem argumentos, lista as branches existentes. Com um nome, cria uma nova branch (sem mudar para ela).

git branch              # lista as branches
git branch nova-feature # cria uma nova branch
git switch / checkout

Alternar entre branches

switch é a forma moderna e recomendada; checkout -b cria e muda numa só etapa.

git switch nova-feature
git checkout -b nova-feature
git merge

Integrar alterações

Junta o histórico de outra branch na branch atual. Normalmente faz-se merge da feature para a main.

git switch main
git merge nova-feature
git branch -d

Apagar uma branch

Depois do merge, a branch da funcionalidade pode ser removida em segurança.

git branch -d nova-feature
Visualização

Como os commits se ramificam

Representação simplificada de uma branch feature criada a partir da main e depois integrada de volta com merge.

main
C1
C2
C5 (merge)
feature/x
C3
C4

C1 → C2: commits feitos diretamente na main. A partir de C2, cria-se a branch feature/x, onde são feitos os commits C3 e C4. Por fim, C5 é o merge commit que traz o trabalho da feature/x de volta para a main.

Quando algo dá errado

Resolução básica de conflitos de merge

Um conflito ocorre quando a mesma linha de um ficheiro foi alterada de forma diferente em duas branches. O Git marca o ficheiro com marcadores especiais para que a pessoa decida qual versão manter.

1. O Git assinala o conflito

Ao tentar fazer merge, o ficheiro fica assim:

<h1>Bem-vindo ao projeto</h1>
<<<<<<< HEAD
<p>Versão da branch main</p>
=======
<p>Versão da branch feature/x</p>
>>>>>>> feature/x

2. Resolver e finalizar

Edite o ficheiro manualmente, escolhendo (ou combinando) o conteúdo correto e removendo os marcadores <<<<<<<, ======= e >>>>>>>.

Depois, marque o ficheiro como resolvido e finalize o merge:

git add index.html
git commit -m "fix: resolve conflito de merge"

💡 Dica: comunicar com a equipa antes de alterar ficheiros partilhados evita muitos conflitos.
